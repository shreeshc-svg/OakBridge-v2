# LinkedIn draft — BA skills → AI builder

I'm a business analyst. This month, an e-commerce site I built started taking real orders.

I used AI tooling to write most of the code, and I'll say that plainly because the interesting part isn't that the code got written. It's what the code couldn't tell me.

AI writes code faster than I can read it. What it cannot do is decide what "finished" means. That was already my job.

Three moments where the BA training did the work:

**A customer got two order confirmation emails.** The code looked correct. It wasn't — two separate paths were both sending, and only a real order exposed it. Chasing a symptom nobody else thought was a bug is a BA reflex, not a coding one.

**We needed admin roles.** Not "add permissions" — I had to decide precisely which sections each person could reach, and which ones nobody should be able to switch off. Writing that specification *was* the task. The implementation fell out of it.

**An external SEO audit arrived listing critical failures.** I checked every claim against the live site. Some were real. Several described the old, compromised domain we'd replaced months earlier. Taking an expert's findings on trust is how you spend a month fixing the wrong thing.

Requirements. Edge cases. Acceptance criteria. Asking the awkward question in the review.

None of that got less valuable when the code started writing itself. It got more.
